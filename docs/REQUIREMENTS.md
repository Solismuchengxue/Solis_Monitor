# Solis Monitor 需求规格

> 状态：稳定需求基线
> 更新日期：2026-07-25
> 状态与实施顺序：见根目录 `TODO.md`

## 1. 文档边界

本文使用稳定编号描述 Solis Monitor 必须满足的功能与非功能需求，供设计、实现、测试和实机验收共同引用。

- `必须`：当前产品基线，不满足即不能视为功能完成。
- `应当`：重要质量目标；受硬件或上游数据限制时允许降级，但必须明确显示。
- `后续`：已经确认方向，但不属于当前可用版本。

本文不记录开发过程、临时问题或完成状态。总体设计见根目录 `DESIGN.md`，协议见 `docs/PROTOCOL.md`，当前任务和后续验收条件见根目录 `TODO.md`。

## 2. 产品范围

| 编号 | 级别 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| SYS-001 | 必须 | 系统由 Windows 桌面端和一台 ESP32-S3 副屏组成。 | PC 端与副屏通过局域网完成指标、配置和控制闭环。 |
| SYS-002 | 必须 | 副屏日常运行只依赖供电和 Wi-Fi，不依赖 USB 数据连接。 | 断开 USB 数据链路后，指标、配网、控制和 OTA 仍可通过局域网完成。 |
| SYS-003 | 必须 | PC 端复用 Libre Hardware Monitor 的硬件访问能力，不重新实现硬件监控内核。 | 硬件指标来自同一进程内 LHM 对象模型；开发者模式仍能进入原始传感器树。 |
| SYS-004 | 必须 | 小屏使用轻量自绘 RGB565 界面，不引入 LVGL。 | 固件资源和绘制链路由 `renderer`、`ui_assets` 和 `ui` 组件完成。 |
| SYS-005 | 必须 | 当前系统只管理一台副屏。 | 普通界面只显示一个当前设备，不提供多设备列表或分组管理。 |

## 3. 硬件与固件基线

| 编号 | 级别 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| HW-001 | 必须 | 主控为 ESP32-S3-WROOM-1-N8R2，使用 8 MiB Flash 和 2 MiB PSRAM。 | 启动时检查 PSRAM；检查失败时停止进入正常 UI。 |
| HW-002 | 必须 | 显示器为 NT35510、800×480 横屏、RGB565。 | 实机方向、RGB 顺序、像素字节序、四角和右边界显示正确。 |
| HW-003 | 必须 | GPIO21 作为唯一日常物理按键。 | 单击、双击和约 5 秒长按能按当前模式规则工作，互不误触发。 |
| HW-004 | 必须 | DHT11 连接 GPIO47，由 ESP32 本地采集。 | 每 2 秒采集；失败时仅清除温湿度 availability，不影响其他链路。 |
| HW-005 | 必须 | 背光支持 20 kHz PWM 和完全关闭。 | PC 可设置 10%–100% 亮度；夜间、失联和睡眠逻辑可关闭背光。 |

详细引脚和电气约束见 `docs/HARDWARE.md`。

## 4. PC 硬件与网络指标

| 编号 | 级别 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| MET-001 | 必须 | CPU 提供名称、占用率、温度、主频和功耗。 | 每个字段独立可用；缺失字段显示 `--`，不以 0 代替。 |
| MET-002 | 必须 | GPU 提供名称、占用率、核心温度、核心主频和功耗。 | 默认优先独立显卡；无有效值时逐字段降级。 |
| MET-003 | 必须 | GPU 显存提供已用量、总量、占用率和显存温度。 | 支持时显示真实值；容量可推导占用率；缺失温度不显示 0°C。 |
| MET-004 | 必须 | 内存提供已用、总量、占用率和可用的内存温度。 | 多条温度取当前最高有效值；无温度传感器时显示 `--`。 |
| MET-005 | 必须 | 物理硬盘分别提供名称、占用率和实时温度。 | 最多同时显示 4 块；告警温度阈值不得冒充当前温度。 |
| MET-006 | 必须 | 网络只采集当前 Windows 出口网卡的上传和下载速度。 | 网卡切换后重新建立计数基线；首样本、计数回退和异常间隔不产生虚假速度。 |
| MET-007 | 必须 | PC 每秒发布一次完整统一快照。 | 同一周期内硬件、网络、Codex 和天气不会分批发布或产生额外序号。 |
| MET-008 | 必须 | 每个可选字段具有独立 availability。 | 单个传感器失败不会把整页或其他模块变为不可用。 |

## 5. Codex 指标

| 编号 | 级别 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| COD-001 | 必须 | 从本机 Codex 会话 JSONL 中选择最后活动的主任务，排除子代理会话。 | 存在更新更晚的子代理时，项目和上下文仍来自最后活动主任务。 |
| COD-002 | 必须 | 独立提供项目名、任务名、模型和推理强度。 | 项目来自 `cwd`，任务来自会话索引，模型与推理强度来自最新 `turn_context`，互不混用。 |
| COD-003 | 必须 | 提供上下文已用 K、总 K 和占用率。 | 数据来自有效 `token_count`；文件追加和截断后仍能恢复读取。 |
| COD-004 | 必须 | 分别提供主周额度和 GPT-5.3-Codex-Spark 周额度的名称、剩余百分比和重置时间。 | 切换项目时额度不得回退到旧样本；后台出现新的重置事件时允许额度恢复。 |
| COD-005 | 必须 | 提供账户累计 Token 和最后活动任务累计 Token 所需字段。 | 小屏当前显示账户累计 Token；字段缺失时显示 `--`。 |
| COD-006 | 必须 | 连续 10 分钟没有新的有效上下文事件后显示“不活跃”。 | 保留最后有效值；出现新事件后自动恢复“活跃”。 |
| COD-007 | 应当 | 内部格式变化必须产生稳定、脱敏的错误类别。 | 诊断信息不得包含会话原文、认证数据或完整本地路径内容。 |

Codex 采集算法与兼容边界见 `docs/CODEX_METRICS.md`。

## 6. 天气与室内环境

| 编号 | 级别 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| ENV-001 | 必须 | PC 通过和风天气 API Key 获取地点、天气描述、最低/最高温、风向、风力等级和图标码。 | 支持 gzip 响应；实况与预报成功后写入同一快照。 |
| ENV-002 | 必须 | 天气配置只要求 API Host、API Key 和单行“经度,纬度”，地区名称由 GeoAPI 自动获取。 | 不显示城市输入框；测试时先根据坐标得到地区名称和 Location ID，测试成功才允许保存。 |
| ENV-003 | 必须 | 中国大陆坐标按 GCJ-02，其他地区按 WGS84。 | 配置界面提供说明和高德坐标查询链接，不承诺自动坐标转换。 |
| ENV-004 | 必须 | API Key 使用当前 Windows 用户保护机制保存。 | 普通界面只显示“已配置”，诊断、日志和复制内容均不出现明文。 |
| ENV-005 | 必须 | 天气和 DHT11 各自独立失败。 | 天气失败不影响 PC 指标；DHT11 失败不影响 Wi-Fi、Codex 或天气。 |
| ENV-006 | 必须 | 短期天气网络失败保留最近有效值，超过有效期后清除。 | 最近值最多保留 3 小时；明确认证错误立即通知，网络错误连续 30 分钟后通知。 |

## 7. 小屏显示与交互

| 编号 | 级别 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| UI-001 | 必须 | 逻辑画布固定为 800×480，面向 3.97 英寸屏幕保证可读性。 | 动态文字和图标不越界、不跨卡片覆盖，长文本按 UTF-8 字符边界截断。 |
| UI-002 | 必须 | 电脑页顶部显示下载、上传、本机 Wi-Fi 图标和 SSID。 | Wi-Fi 断开时显示断连图标和“无连接”；不显示 Windows 网卡名、FPS 或 PC Online 文案。 |
| UI-003 | 必须 | 电脑页上半区为 CPU/GPU，下半区为内存/硬盘。 | 指标内容符合 MET-001 至 MET-005；能同时放下时不轮换。 |
| UI-004 | 必须 | Codex 页顶部显示 DHT11 温湿度与 Codex 活跃状态。 | 使用温湿度图标；不可用字段显示 `--`。 |
| UI-005 | 必须 | Codex 页显示上下文、双周额度、位置天气和累计 Token。 | 项目、模型、推理强度、进度条、重置时间及天气文字排版互不串位。 |
| UI-006 | 必须 | 普通单击切换页面；不提供自动轮换设置。 | 页面切换只由物理按键控制，PC 控制台不提供轮换开关或间隔。 |
| UI-007 | 必须 | 特殊模式具有独占按键语义。 | 发现模式和 AP 模式只接受单击退出，忽略双击和再次长按。 |

## 8. 配网、发现和配对

| 编号 | 级别 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| NET-001 | 必须 | 无有效 Wi-Fi 配置时自动开启 `Solis-Monitor-XXXX` AP；已配置时长按 GPIO21 约 5 秒进入。 | 小屏显示热点名、`192.168.0.1`、约 10 分钟倒计时和“单击退出”。 |
| NET-002 | 必须 | AP 门户支持通配 DNS、Wi-Fi 扫描、SSID、密码、保存连接和恢复默认设置。 | 手机认证弹窗和关闭移动数据后的浏览器均可访问 `http://192.168.0.1/`。 |
| NET-003 | 必须 | 保存成功后关闭 AP 并连接新 Wi-Fi；配置使用双槽 NVS。 | 保存失败或超时不会破坏上一份有效配置。 |
| NET-004 | 必须 | 普通 Wi-Fi 短暂掉线只退避重连，不自动暴露 AP。 | 已配置设备断线时不开放门户；串口救援命令仍可用。 |
| NET-005 | 必须 | STA 联网后局域网仍可访问同一 WebUI。 | 家庭可信局域网内可修改 Wi-Fi；恢复默认设置需要页面二次确认。 |
| NET-006 | 必须 | 恢复设备默认设置清除所有 Wi-Fi、PC 地址、配对关系和令牌，但保留设备名。 | 完成后页面提示重新连接实际 AP 名，设备重启进入 AP 配网。 |
| PAIR-001 | 必须 | 双击 GPIO21 进入发现模式并显示 6 位配对码。 | 配对码每 60 秒刷新，上一组保留 10 秒宽限；页面显示倒计时和单击退出。 |
| PAIR-002 | 必须 | PC 设备向导只列出处于发现模式的同局域网设备。 | 用户选择设备、输入 6 位码后，PC 自动同步 IPv4、端口 18472 和内部令牌。 |
| PAIR-003 | 必须 | 配对成功后双方保存关系；清除 PC 配对只撤销 PC 本地信任。 | 清除后停止设备通知；重新连接必须再次进入发现并输入新配对码。 |
| PAIR-004 | 必须 | 设备向导中的配网入口开启 10 分钟 PC 维护状态。 | 维护期间暂停离线通知，设备提前上线时立即结束；未打开向导时不自动进入维护。 |

配网状态机和恢复规则见 `docs/PROVISIONING.md`。

## 9. PC 控制中心

| 编号 | 级别 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| APP-001 | 必须 | 普通控制台只提供“设备、服务、启动与托盘、固件更新”四页。 | 不在 PC 端重复小屏的硬件、Codex 或天气看板。 |
| APP-002 | 必须 | 设备页显示当前设备信息、设备向导、配对状态、亮度、夜间背光和远程重启。 | 未连接时明确禁用设备控制；连接后读取并保存真实设备设置。 |
| APP-003 | 必须 | 服务页显示设备 API、Codex、天气 API、修复与导出。 | 可编辑天气、重启 PC 服务和复制脱敏诊断信息。 |
| APP-004 | 必须 | 启动页只显示“静默启动”和“开机启动”。 | 关闭和最小化固定进入托盘；托盘菜单只保留同名两个可勾选开关。 |
| APP-005 | 必须 | 开机启动使用最高权限计划任务；静默启动只影响 Windows 开机启动。 | 手动双击始终打开控制台；首次启用计划任务时由 Windows 请求管理员授权。 |
| APP-006 | 必须 | 连续点击版本号 10 次且总时长不超过 10 秒才显示开发者入口。 | 超时或切页清零；关闭开发者模式后必须重新解锁。 |
| APP-007 | 必须 | 恢复 PC 默认设置采用独立危险区域和二次确认。 | 清除配对、天气、启动、通知和 Solis 设置；保留程序、固件、日志和上游传感器配置；重启后打开设备页且不弹向导。 |
| APP-008 | 必须 | 控制台跟随 Windows 深浅色主题和系统强调色。 | 主要页面在两种主题和目标 DPI 下无截断、叠字或失效按钮。 |

## 10. 通信、控制与电源

| 编号 | 级别 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| COM-001 | 必须 | ESP32 通过 HTTP 每秒轮询 PC 的 schema 1 完整快照。 | 连接正常时序号递增；不引入 WebSocket。 |
| COM-002 | 必须 | 设备 API 默认监听 TCP 18472，并使用 Bearer Token。 | 未授权请求被拒绝；协议响应不泄露完整令牌。 |
| COM-003 | 必须 | 传输失败与字段不可用分开表达。 | 连续失败 5 秒后显示链路断开；成功响应后自动恢复。 |
| DEV-001 | 必须 | PC 可设置亮度、夜间背光时段并远程重启副屏。 | 设置保存到设备；重启按钮等待设备真实离线并重新上线后恢复。 |
| DEV-002 | 必须 | 夜间背光默认关闭；启用后按设备本地时间独立执行。 | 默认时段为 23:30–07:30；首次按键只唤醒，30 秒无操作再次熄灭。 |
| DEV-003 | 必须 | PC 连续失联 5 分钟后关闭背光，恢复连接后自动点亮。 | 计时支持首次连接前状态和 32 位毫秒回绕；夜间规则优先。 |

## 11. 更新、恢复与发布

| 编号 | 级别 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| OTA-001 | 必须 | PC 支持选择本地 ESP32-S3 固件执行局域网 OTA。 | 上传前校验芯片、项目、版本、大小和 SHA-256，并显示二次确认。 |
| OTA-002 | 必须 | 固件使用 ESP-IDF 双 OTA 分区、启动确认和失败回滚。 | 新固件未在规定时间上线时 PC 明确提示可能回滚；旧版本可恢复运行。 |
| OTA-003 | 必须 | OTA 使用当前配对令牌且不要求 GPIO0 下载模式。 | 正常升级仅需设备供电和局域网连接。 |
| REL-001 | 必须 | 开发阶段提供解压即用的 Windows 便携版。 | 发布目录包含主程序、依赖、中文资源和通知助手。 |
| REL-002 | 必须 | 稳定版提供 Windows 安装包。 | 用户配置保存在当前 Windows 用户目录，覆盖安装或版本升级后不丢失。 |

## 12. 安全、隐私与可靠性

| 编号 | 级别 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| SEC-001 | 必须 | 普通界面不显示或复制 API Key、Wi-Fi 密码和完整设备令牌。 | 诊断信息和日志通过脱敏检查。 |
| SEC-002 | 必须 | 设备令牌由配对流程自动生成和同步，使用 64 个十六进制字符（32 字节、256 位随机量）并以恒定时间比较。 | 用户不需要手工输入；错误令牌不能读取指标或执行控制。 |
| SEC-003 | 必须 | HTTP 服务只面向可信家庭局域网，不设计互联网暴露。 | 防火墙仅在专用网络放行；文档不建议公网映射。 |
| SEC-004 | 必须 | STA WebUI 在可信局域网内开放，修改 Wi-Fi 和恢复设备默认设置不增加令牌认证。 | 页面明确二次确认恢复操作；此风险在设计文档中保留说明。 |
| NFR-001 | 必须 | 动态硬件和网卡变化不得造成 JIT 异常、崩溃或 UI 集合并发错误。 | 控制中心可见、原始树隐藏和开发者树可见三种状态均通过热插拔回归。 |
| NFR-002 | 必须 | PC 和固件失败必须局部化并可自动恢复。 | 单项 API、传感器或网络失败不阻塞其他指标和 UI 主循环。 |
| NFR-003 | 应当 | PC 指标与小屏刷新保持轻量。 | 正常采集周期为 1 Hz；天气和 DHT11 使用独立低频任务。 |
| NFR-004 | 必须 | 桌面端与固件完成适用构建、自动测试和实机验收后才可发布。 | 验证入口和证据符合 `docs/TESTING.md`，无法执行的检查必须明确记录。 |

## 13. 明确非目标

- 不提供历史趋势图。
- 不管理或限制 Codex 用量。
- 不提供日常传感器筛选；硬件变更时通过开发者模式处理。
- 不提供多副屏管理。
- 不使用 WebSocket、LVGL 或旧独立 PC Agent。
- 不在普通 PC 控制台重复显示小屏仪表盘。
- 不自行实现公网 HTTPS、账户系统或云端中继。
